## S-10 key usage policy (branch `feat/key-usage-policy`)

Per-key usage policy following each applet's specification; the device has
no button (no touch / UIF).

| Applet | Enforced | Spec |
|---|---|---|
| SC-HSM | Key attributes `90` use counter, `91` algorithm list, `92` key domain (only 0) at GENERATE KEY PAIR / GENERATE SYMMETRIC KEY (also P2 `B0`–`B2`) / UNWRAP; checked on SIGN, PSO:CDS, DECIPHER, PSO:DECIPHER, GENERAL AUTHENTICATE (`73`), PSO checksum (`18`), CIPHER (`10`/`11`/`18`), WRAP (`92`); operations without a CardContact ID only on keys without a list; counter spent on flash before the operation (`6A84` exhausted, `6985` not allowed, `6581` write failed); reported in the `CCxx` FCP (`A5 { 90 91 92 }`) | CardContact SmartCard-HSM key use control; OpenSC `card-sc-hsm.h`, `pkcs15-sc-hsm.c` |
| PIV | Slot rules (9A/9C/9E sign, 9D/82–95 ECC CDH only; 9C PIN always, 9E none, others PIN once), retired slots 82–95, Yubico PIN policy `AA` stored and enforced, touch `AB` only 00/01, VERIFY P1=FF, GET METADATA `F7` | SP 800-73-4 Part 1/2, SP 800-78-4; Yubico PIV extensions |
| OpenPGP | `C4` byte 1 (one / several PSO:CDS) writable with PW3 and persisted; DO 93 persisted before the signature leaves, reset with a new SIG key; algorithm attributes valid per role; `7F74` = `81 01 00`; UIF unsupported | OpenPGP Card 3.4 §4.4.3.6, §4.4.3.9, §4.4.3.10, §4.1.3.2, §7.2.10 |

Storage: `P2KP` = `P2K4` + policy (encrypted); objects without a policy
stay `P2K4`, so existing keys load unrestricted and older firmware refuses
a restricted key instead of dropping its policy.  DKEK wrap format version
3 carried the policy (only keys that have one); counted keys are not
exportable.  Superseded by P0 (`CLUSTER_PLAN_V3.md` §3): WRAP writes the
CardContact key blob, whose own field carries the algorithm list (a use
counter has no field, so counted keys stay unexportable); v2/v3 still
UNWRAP for one release.  The CardContact blob keeps the S-08 properties:
KCV and AES-CMAC checked in constant time before any decryption or
parsing, one SW (6A80) for every unauthenticated blob, no padding check
after decryption (lengths are explicit and under the CMAC).
